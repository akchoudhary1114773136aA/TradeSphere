# STOCKLY - User Management Database Template
## Complete Database Schema, Models & Setup

---

## Database Overview

**Database Name:** `stockly`

**Collections:**
1. `users` - User credentials & profiles
2. `holdings` - Stock holdings/portfolio
3. `transactions` - Buy/sell transactions
4. `documents` - KYC documents
5. `auditlogs` - User action tracking (optional)

---

## Collection 1: USERS

### MongoDB Schema Structure

```javascript
{
  _id: ObjectId,                    // Unique ID generated by MongoDB
  
  // Basic Credentials
  email: String,                    // Unique, indexed, lowercase
  password: String,                 // Hashed (bcrypt)
  
  // Profile Information
  fullName: String,                 // User's full name
  phoneNumber: String,              // Optional: Phone number
  avatar: String,                   // Optional: Avatar URL
  
  // Account Status
  isVerified: Boolean,              // Email verification status
  isActive: Boolean,                // Account active/inactive
  accountStatus: String,            // active, suspended, closed
  
  // Dates
  createdAt: Date,                  // Account creation date
  updatedAt: Date,                  // Last update
  lastLogin: Date,                  // Last login timestamp
  
  // Preferences
  currency: String,                 // Default: "INR"
  timezone: String,                 // Default: "IST"
  language: String,                 // Default: "en"
  
  // Settings
  notificationsEnabled: Boolean,    // Notification preference
  emailNotifications: Boolean,      // Email alerts
  
  // KYC Status
  kycStatus: String,                // pending, approved, rejected
  kycSubmittedAt: Date,             // When KYC was submitted
  kycApprovedAt: Date,              // When approved
  
  // Tokens (for password reset, email verification)
  verificationToken: String,        // Email verification token

  twoFactorSecret: String,          // 2FA secret (encrypted)
  
  // Session & Login Tracking
  loginAttempts: Number,            // Failed login count
  lockUntil: Date,                  // Account locked until
  
  // Metadata
  role: String,                     // user, admin, moderator
  tier: String,                     // free, premium, vip
  referralCode: String,             // Unique referral code
  referredBy: ObjectId,             // User who referred (ref: User)
```

## Collection 2: HOLDINGS

### MongoDB Schema Structure

```javascript
{
  _id: ObjectId,                    // Unique ID
  
  // User Reference
  userId: ObjectId,                 // ref: users._id (indexed)
  
  // Stock Information
  stockSymbol: String,              // AAPL, GOOGL, MSFT (uppercase)
  companyName: String,              // Apple Inc., Google LLC
  sector: String,                   // Technology, Finance, Healthcare
  industry: String,                 // Optional: Specific industry
  
  // Quantity & Pricing
  quantity: Number,                 // Shares owned
  averagePrice: Number,             // Average cost per share
  currentPrice: Number,             // Latest market price
  
  // Valuation
  totalCostValue: Number,           // quantity × averagePrice
  currentMarketValue: Number,       // quantity × currentPrice
  gainLoss: Number,                 // currentMarketValue - totalCostValue
  gainLossPercent: Number,          // (gainLoss / totalCostValue) × 100
  
  // Dates
  purchaseDate: Date,               // When first purchased
  lastUpdated: Date,                // Last price update
  createdAt: Date,                  // Record creation
  updatedAt: Date,                  // Record update
  
  // Additional Info
  currency: String,                 // USD, INR, EUR
  notes: String,                    // Optional: User notes
  
  // Price History (Optional)
  priceHistory: [
    {
      price: Number,
      date: Date,
      source: String  // API, manual
    }
  ],
  
  // Target Info (Optional)
  targetPrice: Number,              // Price target
  stopLoss: Number,                 // Stop loss price
}
```

## Setup Script - Create All Collections

```javascript
// Connect to MongoDB
use stockly

// 1. Create Users Collection
db.createCollection("users", {
  validator: {
    $jsonSchema: {
      bsonType: "object",
      required: ["email", "password"],
      properties: {
        _id: { bsonType: "objectId" },
        email: { bsonType: "string" },
        password: { bsonType: "string" },
        fullName: { bsonType: "string" },
        phoneNumber: { bsonType: "string" },
        isVerified: { bsonType: "bool" },
        isActive: { bsonType: "bool" },
        createdAt: { bsonType: "date" },
        updatedAt: { bsonType: "date" }
      }
    }
  }
})

// Create indexes on Users
db.users.createIndex({ email: 1 }, { unique: true })
db.users.createIndex({ verificationToken: 1 }, { sparse: true })
db.users.createIndex({ resetPasswordToken: 1 }, { sparse: true })
db.users.createIndex({ createdAt: -1 })

// 2. Create Holdings Collection
db.createCollection("holdings", {
  validator: {
    $jsonSchema: {
      bsonType: "object",
      required: ["userId", "stockSymbol", "quantity", "averagePrice"],
      properties: {
        _id: { bsonType: "objectId" },
        userId: { bsonType: "objectId" },
        stockSymbol: { bsonType: "string" },
        quantity: { bsonType: "number" },
        averagePrice: { bsonType: "number" },
        currentPrice: { bsonType: "number" }
      }
    }
  }
})

// Create indexes on Holdings
db.holdings.createIndex({ userId: 1, stockSymbol: 1 }, { unique: true })
db.holdings.createIndex({ userId: 1 })
db.holdings.createIndex({ userId: 1, createdAt: -1 })

// 3. Create Transactions Collection
db.createCollection("transactions", {
  validator: {
    $jsonSchema: {
      bsonType: "object",
      required: ["userId", "stockSymbol", "transactionType", "quantity", "pricePerUnit"],
      properties: {
        _id: { bsonType: "objectId" },
        userId: { bsonType: "objectId" },
        transactionType: { enum: ["buy", "sell"] },
        quantity: { bsonType: "number" },
        pricePerUnit: { bsonType: "number" }
      }
    }
  }
})

// Create indexes on Transactions
db.transactions.createIndex({ userId: 1, transactionDate: -1 })
db.transactions.createIndex({ transactionId: 1 }, { unique: true })
db.transactions.createIndex({ status: 1, userId: 1 })

// 4. Create Documents Collection
db.createCollection("documents")
db.documents.createIndex({ userId: 1 })
db.documents.createIndex({ documentNumber: 1 }, { unique: true, sparse: true })

// 5. Create AuditLogs Collection (optional)
db.createCollection("auditlogs")
db.auditlogs.createIndex({ userId: 1, timestamp: -1 })
db.auditlogs.createIndex({ action: 1, timestamp: -1 })
```

## Query Examples

### Find User by Email
```javascript
db.users.findOne({ email: "john@example.com" })
```

### Find All Holdings for a User
```javascript
db.holdings.find({ userId: ObjectId("507f1f77bcf86cd799439011") })
```

### Get Total Portfolio Value
```javascript
db.holdings.aggregate([
  { $match: { userId: ObjectId("507f1f77bcf86cd799439011") } },
  { $group: { _id: null, totalValue: { $sum: "$currentMarketValue" } } }
])
```

### Get All Transactions for User (Last 30 Days)
```javascript
db.transactions.find({
  userId: ObjectId("507f1f77bcf86cd799439011"),
  transactionDate: { $gte: new Date(ISODate().getTime() - 30*24*60*60*1000) }
}).sort({ transactionDate: -1 })
```

### Get Holdings by Sector
```javascript
db.holdings.aggregate([
  { $match: { userId: ObjectId("507f1f77bcf86cd799439011") } },
  { $group: { _id: "$sector", count: { $sum: 1 }, value: { $sum: "$currentMarketValue" } } }
])
```

### Find Profitable Holdings
```javascript
db.holdings.find({
  userId: ObjectId("507f1f77bcf86cd799439011"),
  gainLoss: { $gt: 0 }
}).sort({ gainLoss: -1 })
```

## Database Optimization Tips

### 1. Indexing Strategy
- Always index fields used in queries
- Compound indexes for common filter combinations
- Sparse indexes for optional fields

### 2. Data Archival
- Move old transactions (> 2 years) to archive collection
- Keep active data lean for performance

### 3. Aggregation Pipeline
- Use `$match` early to reduce documents
- Use `$project` to limit fields
- Avoid `$lookup` on large collections

### 4. Connection Pooling
- Use connection pool (default 10 connections)
- Increase for high-traffic apps

### 5. TTL Indexes (Auto-Delete)
```javascript
// Auto-delete reset tokens after 1 hour
db.users.createIndex(
  { resetPasswordExpire: 1 },
  { expireAfterSeconds: 3600, sparse: true }
)
```

## Security Best Practices

### 1. Password Hashing
```javascript
const bcrypt = require('bcryptjs');
const hashedPassword = await bcrypt.hash(password, 10);
```

### 2. Encrypt Sensitive Fields
```javascript
// Encrypt 2FA secret, tokens, etc.
const crypto = require('crypto');
const encrypted = crypto.AES256.encrypt(data, SECRET_KEY);
```

### 3. Index Sensitive Data
```javascript
db.users.createIndex({ email: 1 }, { unique: true })
db.documents.createIndex({ documentNumber: 1 }, { unique: true, sparse: true })
```

### 4. Audit Logging
```javascript
// Log all important actions
db.auditlogs.insertOne({
  userId: user._id,

  entityId: transaction._id,
```
